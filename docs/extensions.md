# GNU C extensions

The compatibility target is C11 and GNU11 on AArch64 and x86-64 Linux,
including the documented GNU extensions available in those dialects. Compare
with GCC using `-std=c11` or `-std=gnu11`. Use `-pedantic-errors` to make
required diagnostics errors. [GNU C chapter](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/C-Extensions.html) · [C dialect options](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/C-Dialect-Options.html)

The test target compares independently written cases with the GCC executable
selected by `MCC_TOOLCHAIN`. To run generated executables for a different
target, provide its glibc paths and pass `--target` and `--runner` to
`tests/check_gnu_extensions.py`.

Taking the address of a nested function creates a heap trampoline tied to the
enclosing function activation. The trampoline mapping is writable during
initialization and read-execute when callable. The stack remains non-executable.
A normal return releases that activation's trampolines. A nonlocal transfer
that skips those returns can leave the skipped activations' mappings allocated.

Atomic operations on naturally aligned 1-, 2-, 4-, and 8-byte objects are
lock-free. The runtime uses sequentially consistent memory accesses for all
memory orders. The fallback for larger or unaligned objects uses a lock scoped
to the linked ELF image. Sharing those objects across separately linked
images or with code using a different fallback runtime is unsupported.

The object-size queries follow addresses, member selections, array offsets,
and conditional expressions. The dynamic form also uses sizes saved when
variable-length arrays are allocated. When an address cannot be traced to
known storage, the queries return the sentinel for the requested mode.
The checked calls use glibc's `__*_chk` interfaces.

Both targets support signed and unsigned `__int128` in their native calling
conventions, including variadic calls. The runtime supplies integer arithmetic
and conversions without libgcc. Conversion from 128-bit integers to floating
point uses the current rounding mode. Sixteen-byte atomics use the runtime's
lock-based path.

Plain `alloca` storage remains live until the function returns. Aligned
allocations can be reclaimed when execution leaves the block, including
through a direct or computed goto. Functions with nonlocal label targets
retain aligned allocation storage until return.
Functions with `__builtin_setjmp` retain aligned allocations across ordinary
block exits and restore the saved stack position on a nonlocal jump.

Extended asm supports register, memory, immediate, and condition-code
operands, matching and alternative constraints, and clobber lists. File-scope
extended asm accepts immediate inputs. A local `register` declaration with an
assembler name selects the register when used directly as an extended asm
operand. Instruction availability follows the integrated assembler.

A file-scope `register` declaration with an assembler register name stores the
variable in that register. Both targets support integers through 64 bits and
pointers in general-purpose registers and `float` and `double` in SIMD
registers. AArch64 also supports `long double` in SIMD registers. The frame and
stack pointers and the AArch64 link register are reserved. Translation units
that use the same variable declare it with the same type and register.
Functions compiled with the declaration can change the register's value
when they return. A call can overwrite a variable in a caller-saved register,
including when that register carries an argument or a return value. The
AArch64 ABI preserves only the low 64 bits of `v8` through `v15`.
[Global register variables](https://gcc.gnu.org/onlinedocs/gcc/Global-Register-Variables.html)

Structures, unions, and fixed arrays of 1, 2, 4, or 8 bytes can occupy a
general-purpose or SIMD register. Aggregates of 16 bytes use a SIMD register.
Code can read and write members and use constant subscripts on register
arrays. Register objects and their subobjects have no address, and atomic
compound updates of register subobjects are unsupported.

Static bit-field initializers use the target's little-endian layout and share
bytes with adjacent fields. The GNU `packed` attribute also supports
bit-fields in structures and unions, including fields that cross a
container boundary. AArch64 and x86-64 apply their own alignment rules to
zero-width fields.

Diagnostic pragmas support `ignored`, `warning`, `error`, `push`, and
`pop`. The compiler uses the settings at the diagnostic's source position,
including after macro expansion. Supported categories are `pedantic`, `cpp`,
`attributes`, `pragmas`, `unknown-pragmas`, `invalid-memory-model`,
`stringop-overflow`, `prio-ctor-dtor`, `deprecated-declarations`,
`designated-init`, `discarded-qualifiers`, and `frame-address`. The `-Wall`
option enables `-Wframe-address`.
`#pragma GCC diagnostic ignored_attributes` and `-Wno-attributes=...` filter
unknown scoped attributes. `#pragma message` emits a note during compilation.
[GNU diagnostic pragmas](https://gcc.gnu.org/onlinedocs/gcc/Diagnostic-Pragmas.html)

## Expressions and control flow

- **Non-returning functions** can use the C11 `_Noreturn` specifier, the `noreturn` macro from `<stdnoreturn.h>`, or the GNU `noreturn` attribute. The GNU attribute also qualifies function pointers. mcc diagnoses explicit returns during parsing and reachable returns during code generation. It emits traps on normal return paths in annotated functions and after calls to them. Nonlocal jumps remain available. [C11 draft, section 6.7.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) · [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html)
- **Switch fallthrough** can be marked with `__attribute__((fallthrough));` before the next `case` or `default` in the same switch. `-Wimplicit-fallthrough` diagnoses unmarked paths during code generation. `-Wextra` enables level 3. Levels 1 through 4 accept increasingly specific comment spellings, level 0 disables the warning, and level 5 requires the attribute. [GCC 11.2 manual, section 6.38](https://gcc.gnu.org/onlinedocs/gcc-11.2.0/gcc.pdf#page=636) · [GNU11 warning options](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Warning-Options.html)
- **Statement expressions** `({ int n = f(); n * n; })` use a block as an expression. The final expression supplies its value. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Statement-Exprs.html)
- **Block-local labels** `__label__ done;` declare a label local to a block, including one inside a macro's statement expression. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Local-Labels.html)
- **Computed `goto`** uses `&&label` to take the address of a label and `goto *ptr;` to branch to it within the same function. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Labels-as-Values.html)
- **Nonlocal jump builtins** save a continuation in an `intptr_t buf[5]`. `__builtin_setjmp(buf)` returns zero on the direct path and one after `__builtin_longjmp(buf, 1)` from a called function. The saved stack position preserves allocations that were live at the checkpoint. The GNU buffer layout works across separately compiled mcc and GCC code on baseline AArch64 and x86-64. The C library's `jmp_buf` has its own layout. [GNU11 manual](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc.pdf) · [GNU nonlocal gotos](https://gcc.gnu.org/onlinedocs/gcc/Nonlocal-Gotos.html)
- **Explicit stack checkpoints** use `__builtin_stack_save()` and `__builtin_stack_restore(saved)` within the same active function invocation. The restore discards stack allocations made after the checkpoint and preserves earlier allocations. Functions with explicit checkpoints retain aligned allocations across ordinary block exits. [GNU stack save and restore](https://gcc.gnu.org/onlinedocs/gcc-11.3.0/gccint.pdf)
- **Frame queries** use `__builtin_frame_address(depth)` and `__builtin_return_address(depth)` with a constant depth. Depth zero refers to the current function. Higher depths require a usable frame-pointer chain. mcc follows that chain on both targets and removes AArch64 pointer authentication codes from saved return addresses. On these targets `__builtin_extract_return_addr` and `__builtin_frob_return_addr` pass the code address through. `__builtin_dwarf_cfa` returns the caller's stack position at the call site. `__builtin_dwarf_sp_column` and `__builtin_eh_return_data_regno` report the register numbers used by the target's unwind ABI. [GNU11 return and frame addresses](https://gcc.gnu.org/onlinedocs/gcc-11.1.0/gcc/Return-Address.html) · [GNU exception handling ABI](https://gcc.gnu.org/onlinedocs/gcc-11.1.0/gccint/Exception-Handling.html)
- **DWARF register sizes** `__builtin_init_dwarf_reg_size_table` writes the target's unwind register sizes into a caller-provided byte array. Baseline x86-64 writes columns 0–16, and baseline AArch64 writes columns 0–31, 46, and 48–96. Other bytes keep their previous values. [GNU unwind table hooks](https://gcc.gnu.org/onlinedocs/gcc-13.2.0/gccint/Exception-Region-Output.html) · [AArch64 DWARF ABI](https://github.com/ARM-software/abi-aa/blob/main/aadwarf64/aadwarf64.rst)
- **Nested functions** can be defined inside functions and can refer to variables in their enclosing scope. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Nested-Functions.html)
- **Omitted middle operand** `x ?: fallback` returns `x` when it is nonzero and otherwise evaluates `fallback`. It evaluates `x` once. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Conditionals.html)
- **Case ranges** `case 1 ... 4:` match a closed interval. GCC also supports them in its experimental C2y mode. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Case-Ranges.html) · [C2y support](https://gcc.gnu.org/projects/c-status.html)

## Types and declarations

- **Type queries and inference** `typeof(expr)` names a type and `__auto_type n = expr;` infers a variable's type from its initializer. C23 standardized `typeof`, `typeof_unqual`, and `auto` type inference. `__typeof__` is GCC's alternate spelling for `typeof`. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Typeof.html) · [C23 support](https://gcc.gnu.org/projects/c-status.html)
- **Array element counts** `_Countof(array)` gives the outermost dimension of a complete array. GCC 16 also implements it in experimental C2y mode. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/_005fCountof.html) · [C2y support](https://gcc.gnu.org/projects/c-status.html)
- **Integer type limits** `_Minof(short)` and `_Maxof(int)` give the minimum and maximum representable values of the given integer types. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/_005fMaxof-and-_005fMinof.html)
- **Alignment queries** `__alignof__` can take a type, object, or function. ISO C11 added `_Alignof(type)`, and C23 provides the `alignof` keyword. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Alignment.html)
- **Member offsets** `__builtin_offsetof(T, member)` implements the standard `offsetof` macro and accepts nested member names and array subscripts. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Offsetof.html)
- **Enumeration declarations** accept fixed underlying types such as `enum color : unsigned char` and forward declarations with a known size. An ordinary enum can be forward-declared as incomplete in GNU mode. For ordinary definitions, `packed` and `-fshort-enums` select the smallest supported integer representation that holds the enumerators. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Enum-Extensions.html)
- **Thread-local storage** `__thread` gives each thread its own instance of a variable on supported targets. The ISO C11 spelling is `_Thread_local`, and C23 provides the `thread_local` keyword. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Thread-Local.html)
- **Alternate keywords** include `__asm__`, `__inline__`, and `__typeof__`. `__extension__` suppresses pedantic diagnostics for the following expression or declaration. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Alternate-Keywords.html)

## Numeric and vector types

- **128-bit integers** `__int128` and `unsigned __int128` are available on targets with an integer mode wide enough to represent them. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/_005f_005fint128.html)
- **Complex arithmetic** includes complex integer types, `__real__` and `__imag__` component access, and literal suffixes such as `3i`. Floating-point `_Complex` types are part of C99. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Complex.html)

mcc supports complex layout and calls, variadic arguments, conversions,
static initializers, and arithmetic for `float`, `double`, and `long double`,
as well as GNU integer complex types and conjugation. Floating-point products
and quotients scale each intermediate product separately to retain terms
with widely differing exponents. The same arithmetic is used for static
initializers and runtime expressions. Arithmetic operators use the bundled
runtime. The C11 `<complex.h>` functions use glibc's math library.
- **Binary floating-point types** include `_Float32`, `_Float64`, and `_Float32x` on AArch64 and x86-64. Each type has its own literal suffix, type identity, and complex counterpart. `_Float32` uses binary32 and keeps its type in variadic calls. `_Float64` and `_Float32x` use binary64. Define `__STDC_WANT_IEC_60559_TYPES_EXT__` before including `<float.h>` for the interchange limits and `<complex.h>` for the glibc complex interfaces. [GNU floating types](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Floating-Types.html) · [WG14 draft for TS 18661-3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1834.pdf)
- **Binary128** uses `_Float128` and `F128` literals on both targets. On x86-64, `__float128` aliases `_Float128`, while `_Float64x` uses x87 extended precision and `__float80` aliases `long double`. On AArch64, `_Float64x` also uses the binary128 representation. The compiler parses quad literals via glibc's `strtold` on AArch64 and `strtof128` on x86-64. The bundled runtime supplies quad arithmetic, complex arithmetic, and conversions, and x86-64 passes scalar quad values in XMM registers. [GNU floating types](https://gcc.gnu.org/onlinedocs/gcc/Floating-Types.html) · [GNU libc float parsing](https://sourceware.org/glibc/manual/2.27/html_node/Parsing-of-Floats.html) · [AMD64 ABI](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex)

  On AArch64, a named one-lane binary128 vector argument uses two SIMD registers, and the return uses one. GCC 16.2 uses a different layout when retrieving that type through `va_arg`. The mixed test covers an isolated named vector argument, and the variadic test uses mcc on both sides.
- **Half precision** uses IEEE binary16 for `_Float16`, with `F16` literals and `__FLT16_*` macros on AArch64 and x86-64. Scalar arithmetic and literals use single-precision evaluation by default. Assignments and casts to `_Float16` round to binary16. Arm's `__fp16` has the same storage layout and promotes to `float` in arithmetic and to `double` in variadic calls. The bundled runtime implements the half-precision conversions and comparison helpers used by the baseline target ABIs. [GNU half precision](https://gcc.gnu.org/onlinedocs/gcc/Half-Precision.html)
- **Bfloat16** uses `__bf16`, `BF16` literals, and `__BFLT16_*` macros on AArch64 and x86-64. `-fexcess-precision=16` rounds literals and each arithmetic result to the declared `_Float16` or `__bf16` format. The runtime converts from wider floating-point formats and 128-bit integers with one rounding step and supports the baseline GNU calling conventions for scalar, complex, and vector modes. [GNU evaluation precision](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html) · [AMD64 ABI](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex)

  On x86-64, mixed links with GCC 15.3 were verified for a single complex bfloat16 argument and result. GCC's `BC` mode can reuse argument registers when another SIMD argument follows and can read a complex bfloat16 variadic argument from a different layout than it writes. mcc passes and retrieves the two components in consecutive SIMD registers when they fit.
- **Decimal floating-point types** use BID on AArch64 and x86-64. `_Decimal32`, `_Decimal64`, and `_Decimal128` have `DF`, `DD`, and `DL` literal suffixes and `SD`, `DD`, and `TD` machine modes. Casts between decimal and binary formats round directly to the destination, including binary16, bfloat16, binary128, and x87 extended precision. Define `__STDC_WANT_IEC_60559_DFP_EXT__` before including `<fenv.h>` to use `fe_dec_getround` and `fe_dec_setround`. The runtime supports five rounding modes and sticky exception flags exposed through the GNU `__dfp_*` functions. A new thread starts with nearest-even rounding and clear decimal flags. An executable and the shared libraries it links with mcc use the same state within each thread. The GNU decimal exceptions are separate from the system binary `fenv` flags. Compile-time constants use nearest-even rounding. The runtime supplies the GNU BID entry points for mixed links. [GNU decimal types](https://gcc.gnu.org/onlinedocs/gcc-11.2.0/gcc/Decimal-Float.html) · [GNU BID runtime ABI](https://gcc.gnu.org/onlinedocs/gccint/Decimal-float-library-routines.html) · [WG14 TS 18661-2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1912.pdf)
  The TS 18661-2 pragma `STDC FENV_DEC_ROUND` is outside the GNU11 compatibility target. GCC 16.2 on AArch64 and GCC 15.3 on x86-64 both ignore that pragma in GNU11 mode.
- **Fixed-point types** include `_Fract` and `_Accum` on supported targets. The GNU11 reference compilers reject these types on AArch64 and x86-64 Linux. [GNU fixed point](https://gcc.gnu.org/onlinedocs/gcc/Fixed-Point.html)
- **Vector types** use `__attribute__((vector_size(16)))` on an integer or floating-point base type. mcc supports lane indexing, elementwise operators, scalar broadcasts, same-size casts, and the `__builtin_convertvector`, `__builtin_shuffle`, and `__builtin_shufflevector` builtins. The tests cover the baseline AArch64 and x86-64 Linux calling conventions, including wide vectors, aggregates with vector fields, and variadic arguments. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc/Vector-Extensions.html)
- **Machine modes** select a representation with `__attribute__((mode(name)))`. mcc supports integer modes from `QI` through `TI`, the `byte`, `word`, and `pointer` aliases, and `BF`, `HF`, `SF`, `DF`, and `TF` floating modes. x86-64 also supports the `XF` mode for x87 extended precision. The corresponding complex modes, integer modes on enum definitions, and the legacy vector modes for supported lane types are also supported. [GNU attributes](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html) · [Machine modes](https://gcc.gnu.org/onlinedocs/gccint/Machine-Modes.html)

## Arrays, structures, and unions

- **Variable-length arrays** support multiple dimensions, typedefs, pointers,
  and function parameters. GNU parameter forward declarations let an array
  parameter use a bound from a later parameter. The compiler retains evaluated
  bounds for pointer arithmetic and `sizeof` and evaluates variably modified
  `typeof` operands when the resulting type is used. [GCC arrays](https://gcc.gnu.org/onlinedocs/gcc-15.2.0/gcc/Variable-Length.html) · [GCC typeof](https://gcc.gnu.org/onlinedocs/gcc/Typeof.html)
- **Variable-length members** in block-scope structures and unions use saved
  bounds to calculate member offsets and aggregate sizes. Array indexing,
  assignment, empty initialization, passing and returning aggregates by value,
  and variadic arguments use those sizes. [GCC arrays](https://gcc.gnu.org/onlinedocs/gcc/Variable-Length.html)
- **Zero-length arrays** such as `char data[0]` are accepted as trailing members. GCC also supports some extensions to standard C99 flexible members (`data[]`), including static initialization of a top-level object. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Zero-Length.html)
- **Empty structures** may have no members and have size zero in GNU C. GCC also allows flexible array members in unions and as the sole member of a structure. [Empty structures](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Empty-Structures.html) · [Flexible members in unions](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Flexible-Array-Members-in-Unions.html) · [Flexible members alone in structures](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Flexible-Array-Members-alone-in-Structures.html)
- **Unnamed members** expose members of an anonymous structure or union through the containing object. C11 standardized tagless forms. `-fms-extensions` and `-fplan9-extensions` enable additional forms. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Unnamed-Fields.html)
- **Transparent unions** accept arguments matching a member of a
  `transparent_union` parameter, including the GNU null and void pointer
  conversions. Named parameters use the first member's calling convention.
  A typedef with the attribute has its own type identity. Mixed links with GCC
  are tested on AArch64 and x86-64. [GNU type attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Type-Attributes.html)
- **Casts to union types** such as `(union value)42` create a union value if the operand's type matches a member type. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Cast-to-Union.html)
- **Range designators** such as `[0 ... 3] = 1` and `[0 ... 3].field = value` initialize multiple array elements or their subobjects. Each initializer expression that contributes to the result is evaluated once for the entire range. GNU11 also accepts the legacy `[i] value` and `name: value` forms. Single-index `[i] =` and field `.name =` designators are part of C99. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Designated-Inits.html)
- **Designated initialization attributes** on structure definitions enable `-Wdesignated-init` for positional member initializers. Use `-Wno-designated-init` to suppress the warning or `-Werror=designated-init` to make it an error. [GNU type attributes](https://gcc.gnu.org/onlinedocs/gcc-11.4.0/gcc/Common-Type-Attributes.html)
- **Compound literals in static initializers** can initialize objects of static storage duration from a matching compound literal with constant elements. Ordinary compound literals were introduced in C99. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Compound-Literals.html)
- **Other C99 features accepted in C90 mode** include subscripting an array member of a returned structure and using runtime expressions in automatic aggregate initializers. [Array subscripting](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Subscripting.html) · [Aggregate initializers](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Initializers.html)

## Language semantics and linkage

- **`void *` and function-pointer arithmetic** treats `void` and function types as size one for pointer arithmetic and `sizeof`. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Pointer-Arith.html)
- **Variadic pointer arguments** can be retrieved with `va_arg(ap, void *)` regardless of the pointer type passed, under the POSIX XSI extension implemented by GCC. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Variadic-Pointer-Args.html)
- **Pointers to qualified arrays** permit conversions such as `int (*)[5]` to `const int (*)[5]`. C23 standardized the underlying array qualification rules. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Pointers-to-Arrays.html) · [C23 support](https://gcc.gnu.org/projects/c-status.html)
- **Old-style function definitions** can inherit an argument type from a prior prototype in the cases described by GCC, including some mismatches caused by default argument promotions. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Function-Prototypes.html)
- **Qualified function types** interpret `const` on a function typedef like GCC's `const` function attribute and `volatile` like `noreturn`. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Const-and-Volatile-Functions.html)
- **GNU89 `inline` linkage** is selected by `-std=gnu89`, `-fgnu89-inline`, or the `gnu_inline` attribute. Later C modes normally use ISO C99 inline semantics. A call without an external definition in its translation unit uses the definition supplied by another object. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Inline.html)
- **Volatile accesses** follow GCC's documented rules, including what a discarded read does and how volatile and ordinary accesses are ordered. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Volatiles.html)

## Tokens and preprocessing

- **Variadic macro extensions** include named packs (`args...`) and GNU comma deletion with `, ##__VA_ARGS__` when the variable argument is omitted. ISO C99 introduced variadic macros, and C23 added `__VA_OPT__` and permits omitting the variable argument. [GNU CPP manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/cpp/Variadic-Macros.html)
- **Source spelling extensions** include `$` in identifiers on most targets, whitespace between a backslash and a spliced newline, the `\e` escape for ESC, and raw strings such as `R"(C:\tmp)"` in `gnu99` and later GNU modes. [Identifiers](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Dollar-Signs.html) · [Newlines](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Escaped-Newlines.html) · [ESC](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Character-Escapes.html) · [Raw strings](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Raw-String-Literals.html)
- **Function-name identifiers** `__FUNCTION__` and `__PRETTY_FUNCTION__` give the function name in GNU C. ISO C99 added `__func__`. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Function-Names.html)
- **Features accepted before their ISO modes** include `long long`, `_Bool`, `//` comments, mixed declarations and statements, and hexadecimal floating constants such as `0x1.8p+1` (C99). Binary constants such as `0b1010` and labels before declarations or at the end of blocks are standard since C23. [Integers](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Long-Long.html) · [Boolean type](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Boolean-Type.html) · [Comments](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/C_002b_002b-Comments.html) · [Declarations and labels](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Mixed-Labels-and-Declarations.html) · [Hex floats](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Hex-Floats.html) · [Binary constants](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Binary-constants.html)
- **Wrapper headers** can use `#include_next` to resume include lookup after the directory where the current header was found. [GNU CPP manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/cpp/Wrapper-Headers.html)
- **System headers** can use `#pragma GCC system_header` to suppress diagnostics from ordinary GNU extensions and whitespace in line continuations in the remainder of an included file. `-Wsystem-headers` enables those diagnostics. mcc keeps glibc's empty compatibility macros for `__attribute__` and `__extension__` within system headers so the keywords remain available in application code. It preserves glibc's `noreturn` declaration attributes during expansion. [GNU CPP manual](https://gcc.gnu.org/onlinedocs/cpp/System-Headers.html)
- **Preprocessor pragmas** `#pragma GCC warning "message"` and `#pragma GCC error "message"` can also be invoked from macros via `_Pragma`. `#pragma GCC dependency "file" message` searches the include path and warns when the dependency is newer than the current source file. `#pragma GCC poison name` diagnoses later uses of an identifier, including names produced by token pasting. Macro replacement text recorded before the pragma can still refer to the name. [GNU CPP manual](https://gcc.gnu.org/onlinedocs/cpp/Pragmas.html)
- **Predefined macros and feature checks** include `__GNUC__`, `__COUNTER__`, `__has_builtin(...)`, and `__has_attribute(...)`. [Predefined macros](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/cpp/Common-Predefined-Macros.html) · [Built-in checks](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/cpp/_005f_005fhas_005fbuiltin.html) · [Attribute checks](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/cpp/_005f_005fhas_005fattribute.html)

## Attributes, pragmas, and target features

- **GNU attributes** use `__attribute__((...))` or `[[gnu::...]]` syntax. Examples include `format`, `nonnull`, `cleanup`, `packed`, `aligned`, `section`, `weak`, and `visibility`. [Common attributes](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Common-Attributes.html) · [Target-specific attributes](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Target-Specific-Attributes.html)
- **Explicit alignment** C11 `_Alignas` and `<stdalign.h>` set the alignment of an object or member. GNU `aligned` also applies to function declarations, aggregate definitions, typedefs, and individual pointer levels. A type attribute can change alignment while keeping the original size. Both targets support power-of-two alignments through 64 KiB. [C11 draft](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) · [GNU attribute syntax](https://gcc.gnu.org/onlinedocs/gcc/Attribute-Syntax.html)
- **Structure packing** `#pragma pack(n)` caps member alignment in completed structures and unions. The stack supports `push`, `pop`, and named entries across include files. `#pragma pack()` restores the compilation default, which can be set by `-fpack-struct=n`. Bare `-fpack-struct` forces one-byte packing. The compiler checks where pack directives occur, and `-E` preserves their order and stack operations. Use the same ABI options when compiling the preprocessed file. [Structure-layout pragmas](https://gcc.gnu.org/onlinedocs/gcc/Structure-Layout-Pragmas.html)
- **Weak symbols and aliases** `weak` and `#pragma weak` mark external functions and objects as weak. The `alias("name")` attribute and `#pragma weak name = target` define aliases for symbols defined in the same translation unit. `weakref("target")` can refer to an undefined symbol through a static declaration. A direct reference to the same target keeps its usual linkage requirements. Weak references alone leave archive members unselected and allow `--as-needed` to omit their shared libraries. [GNU common attributes](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html) · [Weak pragmas](https://gcc.gnu.org/onlinedocs/gcc/Weak-Pragmas.html)
- **Symbol visibility** `visibility("mode")`, `#pragma GCC visibility push(mode)`, and `-fvisibility=mode` accept `default`, `hidden`, `protected`, and `internal`. The pragma applies to declarations until the matching `pop`. The compiler option sets the default for definitions with external linkage. Hidden and internal symbols are private to the linked executable or shared library. Protected definitions are exported and references within the defining module bind to its own definition. [GNU visibility pragmas](https://gcc.gnu.org/onlinedocs/gcc/Visibility-Pragmas.html) · [ELF symbol visibility](https://gabi.xinuos.com/elf/05-symtab.html#symbol-visibility)
- **Constructors and destructors** `constructor` and `destructor` register function definitions to run on startup and shutdown. Optional priorities default to 65535. Priorities from 0 to 100 are reserved for the implementation and produce a warning. Within the linked executable or shared library, constructors run in ascending priority and destructors in descending priority. [GNU function attributes](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html)
- **Automatic cleanup** `cleanup(function)` calls the named function with the address of the automatic variable when ordinary control flow leaves its scope. Cleanups run in reverse declaration order, including on `return`, `break`, `continue`, direct `goto`, and `asm goto`. Computed and nonlocal gotos bypass callbacks for the scopes they abandon. [GNU variable attributes](https://gcc.gnu.org/onlinedocs/gcc/Common-Variable-Attributes.html)
- **Named sections** `section("name")` places a function or an object with static or thread storage in a named ELF input section. The linker combines compatible custom sections of the same name and collects standard section families such as `.text.*` and `.bss.*` in their usual output sections. References to `__start_NAME` and `__stop_NAME` delimit a custom non-TLS section whose name is a C identifier. [GNU attributes](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html) · [GNU linker orphan sections](https://sourceware.org/binutils/docs/ld/Orphan-Sections.html)
- **Passing structures** On AArch64 and x86-64, zero-width bit-fields affect layout according to the target. By-value calls and returns classify the structure using its remaining members and completed size. This follows the ABI used by GCC 12 and later. [GCC ABI notes](https://gcc.gnu.org/gcc-12/changes.html#zero_width_bitfields)
- **Pragmas** include `#pragma GCC diagnostic`, `#pragma GCC target`, `#pragma GCC optimize`, `#pragma GCC unroll`, `#pragma pack`, `#pragma weak`, and `#pragma push_macro` / `pop_macro`. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Pragmas.html)
- **Named address spaces** qualify types on supported targets, for example `__flash` on AVR or `__seg_fs` on x86. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Named-Address-Spaces.html)
- **Inline assembly** includes basic `asm`, extended `asm` with operands and clobbers, `asm goto`, custom assembler names, and explicit register variables. [GCC manual](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Using-Assembly-Language-with-C.html)
- **OpenMP and OpenACC** directives are enabled with `-fopenmp` and `-fopenacc`, respectively. [OpenMP](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/OpenMP.html) · [OpenACC](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/OpenACC.html)

## Compiler built-ins

- **Type and compile-time queries** include `__builtin_types_compatible_p`, `__builtin_choose_expr`, `__builtin_constant_p`, and `__builtin_classify_type`. Type classification accepts a type name or an expression. A single expression is unevaluated and is classified after the default argument conversions. A type name retains its category, including array and function types. [GNU builtins](https://gcc.gnu.org/onlinedocs/gcc/Other-Builtins.html)
- **Attribute queries** `__builtin_has_attribute(subject, attribute)` accepts a type name or an unevaluated expression and returns a compile-time `_Bool` for recognized GNU attributes. A query can include arguments, such as `aligned(32)`, `section(".data")`, or `cleanup(release)`. It distinguishes declared attributes from default layout and alignment. Querying `mode` returns false with a diagnostic, as in GCC. [GNU11 attribute queries](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Other-Builtins.html)
- **Unused function results** The `warn_unused_result` attribute applies to functions and function types, including callback types. Discarding a marked call's result can produce `-Wunused-result`, including when the call is explicitly cast to `void`. The warning is enabled by default during code generation. It can be disabled with `-Wno-unused-result` or controlled with the diagnostic pragma. [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html) · [GNU warning options](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Warning-Options.html)
- **Call diagnostics** A function declaration with `error("message")` or `warning("message")` attaches a diagnostic to direct calls that remain reachable during code generation. `-Wno-attribute-warning` or a diagnostic pragma can suppress warnings. [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html)
- **Variadic sentinels** The `sentinel` attribute on a variadic function type checks for an explicit null pointer in its final variadic argument. `sentinel(position)` counts backward from the end of the call. `-Wformat` and `-Wall` enable these diagnostics for direct and indirect calls, including the GNU built-ins for `execl`, `execlp`, and `execle`. [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html)
- **Pointer attributes** `nonnull` checks null pointer arguments at direct and indirect calls. An explicit parameter list uses one-based positions, and an omitted list covers pointer arguments. `-Wall` enables `-Wnonnull` and `-Wnonnull-compare`. The latter diagnoses comparisons of the original parameter value against null inside a definition. `returns_nonnull` lets code generation simplify null tests while evaluating the call. `-fno-delete-null-pointer-checks` preserves those tests. [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html) · [GNU11 warning options](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Warning-Options.html)
- **Calls without a PLT stub** `noplt` uses the GOT to call a function whose definition may be preempted. `-fno-plt` applies this to all such calls, and `-fplt` restores the default for functions without the attribute. Internal calls and calls to hidden or protected functions branch directly. [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html) · [GNU11 code-generation options](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Code-Gen-Options.html)
- **Patchable function entries** `-fpatchable-function-entry=N[,M]` reserves `N` NOP instructions, placing `M` before the function symbol. The `patchable_function_entry` attribute overrides the option for individual functions and a size of zero disables padding. On AArch64 and x86-64, `__patchable_function_entries` records the start addresses of the padding. [GNU11 instrumentation options](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Instrumentation-Options.html) · [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html)
- **Buffer access contracts** `access(mode, pointer[, size])` describes how a call accesses a pointer argument. A size argument counts elements of the pointed-to type, or bytes for `void *`. The compiler diagnoses provable overreads and overwrites of known objects and allocations, negative sizes, and null arguments paired with positive sizes. It infers size bounds from integer expressions, local assignments, and branch comparisons, including for 128-bit size arguments. Allocation bounds come from the ranges of the arguments evaluated at the call, including both dimensions of `alloc_size(n, m)`. Ranged pointer offsets bound the bytes remaining in the object or subobject. For a tracked local pointer, each assignment that can reach the call contributes a bound calculated at that assignment. A bounds warning requires every possible target to be too small. For `read_only` and `read_write` calls, `-Wuninitialized` and `-Wmaybe-uninitialized` diagnose known local storage with no preceding initialization on the paths to the call. The contracts propagate through function typedefs and compatible redeclarations. [GNU11 function attributes](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Common-Function-Attributes.html)
- **Source location builtins** `__builtin_LINE()`, `__builtin_FILE()`, and `__builtin_FUNCTION()` return the logical line, file, and enclosing function at the call site. The function name is empty at file scope. [GNU11 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Other-Builtins.html)
- **Floating-point format builtins** construct infinities and quiet or signaling NaNs, inspect classification and signs, copy signs, and perform ordered and unordered comparisons. Constructors include the decimal `__builtin_infdN`, `__builtin_nandN`, and `__builtin_nansdN` spellings. Decimal NaN constructors produce a zero payload, as observed with GCC. The compiler folds constant operands and uses the same bit-level operations in the bundled runtime for dynamic operands. [GNU floating-point format builtins](https://gcc.gnu.org/onlinedocs/gcc/Floating-Point-Format-Builtins.html)
- **Type-generic mathematics** uses `__builtin_tgmath` to select a prototyped function from a list using the types of its generic arguments. It supports real and complex function families, binary interchange and extended types, and the ordered fallback for narrowing functions. glibc's `<tgmath.h>` uses the built-in for its C11 macros and binary interchange extensions. [GNU built-ins](https://gcc.gnu.org/onlinedocs/gcc-11.2.0/gcc/Other-Builtins.html) · [WG14 draft for TS 18661-3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1834.pdf)
- **Integer operations** include checked addition, subtraction, and multiplication through `__builtin_*_overflow` and `__builtin_*_overflow_p`, unsigned arithmetic with carry or borrow, scalar bit operations such as `__builtin_popcount` and `__builtin_clz`, and byte swaps such as `__builtin_bswap32`. [Overflow checks](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Integer-Overflow-Builtins.html) · [Bit operations](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Bit-Operation-Builtins.html) · [Byte swaps](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Byte-Swapping-Builtins.html)
- **Memory and control flow** include `__builtin_alloca`, `__builtin_object_size`, `__builtin_expect`, and `__builtin_unreachable`. [Stack allocation](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Stack-Allocation.html) · [Object sizes](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Object-Size-Checking.html) · [Other built-ins](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Other-Builtins.html)
- **Pointer extension** `__builtin_extend_pointer(p)` returns the hardware address as an `unsigned long` on both supported LP64 targets. [GNU11 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.3.0/gcc/Other-Builtins.html)
- **Branch and alignment hints** `__builtin_expect_with_probability` and `__builtin_assume_aligned` evaluate their arguments and return the first argument with the declared result type. mcc validates the probability and uses its normal branch and memory code generation. [GNU11 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Other-Builtins.html)
- **Speculation barrier** `__builtin_speculation_safe_value(value, fallback)` evaluates its arguments, executes a speculation barrier and returns `value` with its integer or pointer type. The fallback is optional. mcc defines `__HAVE_SPECULATION_SAFE_VALUE` and emits `dsb sy` followed by `isb` on AArch64 and `lfence` on x86-64 Linux. [GNU11 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Other-Builtins.html) · [Arm barrier guidance](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Security%20Update%2008%20June%202020/Straight-line_Speculation-v1.0.pdf) · [Intel barrier guidance](https://www.intel.com/content/www/us/en/developer/articles/technical/software-security-guidance/technical-documentation/hardware-behavior-related-to-speculative-execution.html)
- **Thread pointer** `__builtin_thread_pointer()` returns the current thread's ABI pointer as `void *`. It reads `TPIDR_EL0` on AArch64 and the thread control block's self pointer at `%fs:0` on x86-64 Linux. Both targets diagnose `__builtin_set_thread_pointer` calls. [AArch64 System V ABI](https://github.com/ARM-software/abi-aa/blob/main/sysvabi64/sysvabi64.rst) · [x86-64 System V ABI](https://gitlab.com/x86-psABIs/x86-64-ABI)
- **Floating-point environment registers** AArch64 provides `__builtin_aarch64_get_fpcr`, `__builtin_aarch64_set_fpcr` and the corresponding FPSR builtins, with both 32-bit and `64` forms. x86-64 provides `__builtin_ia32_stmxcsr` and `__builtin_ia32_ldmxcsr` to read and write MXCSR. [GNU11 AArch64 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/AArch64-Built-in-Functions.html) · [Intel instruction reference](https://cdrdv2-public.intel.com/671110/325383-sdm-vol-2abcd.pdf)
- **Cache builtins** emit target prefetch instructions for `__builtin_prefetch`. AArch64 uses separate read and write hints. x86-64 uses the baseline locality hints for either access. `__builtin___clear_cache` synchronizes the AArch64 instruction cache through mcc's runtime. On x86-64 it evaluates its two pointer arguments. [GNU11 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Other-Builtins.html) · [Arm cache maintenance](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/caches-self-modifying-code-implementing-clear-cache)
- **Clearing padding** with `__builtin_clear_padding(ptr)` clears unused bytes and bits in the object representation. A union retains any bit used by at least one member, including whole bytes occupied by its direct bit-fields. The builtin handles packed bit-fields, fixed and variable-length arrays, and x86-64 extended-precision padding. It diagnoses flexible array members and records with variable-length members. [GNU11 builtins](https://gcc.gnu.org/onlinedocs/gcc-11.5.0/gcc/Other-Builtins.html)
- **Allocation size** `alloc_size(n)` and `alloc_size(n, m)` describe the size in bytes of memory returned by a function or function pointer. The same inference applies to standard declarations of `malloc`, `calloc`, `realloc`, and `aligned_alloc`, their `__builtin_` forms, and the stack allocation builtins. Runtime sizes are captured from the evaluated arguments and retained when the pointer is copied directly to another local. Static queries require a consistent constant extent. `-fno-builtin`, `-fno-builtin-NAME`, and `-ffreestanding` control recognition of ordinary library names. Explicit `__builtin_` forms and `alloc_size` annotations retain their semantics in these modes. [GNU library builtins](https://gcc.gnu.org/onlinedocs/gcc/Library-Builtins.html) · [Object-size checking](https://gcc.gnu.org/onlinedocs/gcc/Object-Size-Checking.html)
- **Atomics and target intrinsics** include the `__atomic_*` family, the older `__sync_*` family, and machine-specific built-ins. [Atomic operations](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/_005f_005fatomic-Builtins.html) · [Legacy atomics](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/_005f_005fsync-Builtins.html) · [Target intrinsics](https://gcc.gnu.org/onlinedocs/gcc-16.2.0/gcc/Target-Builtins.html)
